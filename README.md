# PC Assistant Bot + JARVIS

Личный ассистент для управления своим Windows-ПК. Работает только с заранее описанными действиями (allowlist), а не как удалённый доступ.

Один и тот же набор разрешённых действий доступен тремя способами:

| Канал | Запуск | Нужен токен Telegram |
|---|---|---|
| Telegram-бот | `.\scripts\run-bot.ps1` | да |
| JARVIS, текст | `.\scripts\run-jarvis.ps1` | нет |
| JARVIS, голос (push-to-talk) | `.\scripts\run-jarvis.ps1 --voice` | нет |

## Быстрый старт (PowerShell)

Нужен Python 3.11–3.13 (проверено на 3.13).

```powershell
git clone https://github.com/h4zvenn/safe-pc-assistant-bot
cd safe-pc-assistant-bot
powershell -ExecutionPolicy Bypass -File .\scripts\setup.ps1     # .venv + зависимости + .env из шаблона
powershell -ExecutionPolicy Bypass -File .\scripts\check.ps1     # тесты и диагностика
powershell -ExecutionPolicy Bypass -File .\scripts\run-jarvis.ps1 # текстовый режим
```

Варианты установки: `-NoVoice` (только Telegram и текст), `-Gpu` (CUDA-библиотеки для видеокарты NVIDIA, около 1 ГБ), `-DownloadModel` (скачать модель распознавания сразу). Если PowerShell ругается на политику выполнения, добавляй `-ExecutionPolicy Bypass`, как выше, или выполни `Set-ExecutionPolicy -Scope Process Bypass`.

То же вручную:

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-voice.txt pytest
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m jarvis
```

Файлы зависимостей: `requirements.txt` (бот и текст), `requirements-voice.txt` (+ распознавание, микрофон, управление плеером), `requirements-gpu.txt` (+ CUDA), `requirements-dev.txt` (+ pytest).

## Настройка

### `.env`

`.env.example` содержит все переменные с заглушками. Скопируй его в `.env` (это делает `setup.ps1`, существующий `.env` он не трогает). `.env` в Git не попадает, токен маскируется в логах.

Для Telegram нужны:

- `BOT_TOKEN` — токен от @BotFather в виде `1234567890:AAH...`, без кавычек и лишних префиксов;
- `AUTHORIZED_USER_IDS` — твой числовой Telegram id (например, через @userinfobot).

`AUTHORIZED_CHAT_IDS` необязателен и только сужает доступ. Если задан только он, доступ получают личные чаты перечисленных пользователей, участники групп не авторизуются никогда.

Для локального JARVIS токен не нужен.

### `data/*.yaml`

Все пути определяются через переменные Windows (`%LOCALAPPDATA%`, `%APPDATA%`, `%ProgramFiles%`, `%ProgramFiles(x86)%`, `%USERPROFILE%`), жёстких путей к чужому профилю нет. Отсутствующая переменная заменяется стандартным значением.

- `apps.yaml` — приложения: `paths` (список кандидатов, берётся первый существующий), `args`, `process_names`, `aliases` (как называть голосом, ru и uk), `allow_close`. Если приложение не установлено, ошибка появляется только при попытке его открыть, остальные работают.
- `scenarios.yaml` — сценарии из шагов `open_app`, `health_check`, `ping_check`, `show_heavy_apps`, `set_volume`, `mute_volume`; `aliases` для голоса; `require_confirmation`.
- `games.yaml` — игры (`steam_app_id`, `aliases`) и процессы для игрового статуса.
- `folders.yaml` — папки и ограничения для `/files`.
- `alerts.yaml`, `users.yaml`, `urls.yaml`, `scripts.yaml` — зарезервированы, код их пока не читает.

Все читаемые файлы проверяются при старте: неизвестный шаг сценария, несуществующее приложение в сценарии, громкость вне 0–100, некорректный хост, сломанный YAML дают понятную ошибку со всем списком проблем. Отсутствующие `.exe` и папки только предупреждения. Проверить вручную: `.\scripts\run-jarvis.ps1 --check`.

## Telegram

```powershell
.\scripts\run-bot.ps1            # запуск
.\.venv\Scripts\python.exe bot.py --check   # проверить .env и YAML без подключения
```

Команды: `/start`, `/help`, `/status`, `/processes`, `/ping`, `/gaming`, `/cs2`, `/apps`, `/open <id>`, `/close <id>`, `/runningapps`, `/files`, `/media`, `/power`, `/scenarios`, `/scenario <id>`. Меню с кнопками открывается через `/start`.

## JARVIS: текстовый режим

```powershell
.\scripts\run-jarvis.ps1                              # интерактивно
.\scripts\run-jarvis.ps1 --once "Покажи состояние ПК"
.\scripts\run-jarvis.ps1 --dry-run                    # проверка разбора без действий в системе
```

Примеры (русский и украинский): «Открой Steam», «Відкрий Discord», «Покажи состояние ПК», «Громкость 30 процентов», «Сделай потише», «Громче на 20», «Поставь музыку на паузу», «Запусти игровой режим», «Зайди на ютуб», «Найди в ютубе котиков», «Открой загрузки», «Который час», «Поставь таймер на 5 минут», «Сверни все окна», «Сделай скриншот», «Заблокируй компьютер», «Выключи звук», «Следующий трек», «Закрой Discord», «Выключи компьютер».

Всё, что не команда, уходит в разговор с моделью (см. ниже). Новые возможности добавляются как зарегистрированные действия: описание в `actions/service.py`, фразы в `jarvis/intent.py`, а модель Ollama подхватывает их автоматически из реестра. Произвольные команды ПК не выполняются никогда.

Если команда неоднозначна, JARVIS уточняет: «Какую игру или режим запустить: CS2, Valorant, Gaming?», «На сколько процентов поставить громкость?», «Ты имел в виду Discord?». Ответить можно названием или номером.

## JARVIS: голос

```powershell
.\scripts\run-jarvis.ps1 --list-mics              # устройства ввода
.\scripts\run-jarvis.ps1 --mic-test               # открыть микрофон на 1 с и показать уровень (ничего не сохраняется)
.\scripts\run-jarvis.ps1 --voice                  # режим push-to-talk
.\scripts\run-jarvis.ps1 --voice --ptt-key mouse4 # другая клавиша
.\scripts\run-jarvis.ps1 --wav C:\путь\фраза.wav  # распознать файл и выполнить команду
```

- **Push-to-talk.** Запись идёт только пока зажата клавиша (по умолчанию `F9`; `JARVIS_PTT_KEY` или `--ptt-key`: `F1`–`F24`, буквы, `scrolllock`, `ctrl+space`, `mouse4`/`mouse5`). Программа читает состояние только этой клавиши, глобального перехвата клавиатуры нет. Индикатор: строка `[REC ●] 1.2 c` в консоли и короткие звуковые сигналы начала и конца (`JARVIS_BEEPS=false` отключает).
- **Постоянное прослушивание.** `.\scripts\run-jarvis.ps1 --listen`: микрофон открыт, фразы выделяются автоматически (по паузе около 0,8 с), реакция только на обращение: «Джарвис, открой Steam», «Джарвис, как дела?». После ответа около 8 секунд (`JARVIS_FOLLOWUP_SECONDS`) можно продолжать без обращения, а одно слово «Джарвис» просто «будит» ассистента. Речь без обращения пропускается, текст не выводится. Клавиша push-to-talk в этом режиме тоже работает и обращения не требует. Свои реплики JARVIS не слышит (звук во время ответа отбрасывается). `--no-wake-word` убирает обращение (реагирует на любую речь, не рекомендуется рядом с телевизором). В шумной комнате поднимите `JARVIS_LISTEN_THRESHOLD` (например, `0.05`). Подтверждение выключения и закрытия приложений и здесь только с клавиатуры. Аудио остаётся в памяти и наружу не уходит.
- **Микрофон.** По умолчанию системный. Другой выбирается через `JARVIS_INPUT_DEVICE` (номер или имя из `--list-mics`).
- **Распознавание** локальное, faster-whisper, русский и украинский (язык выбирается между этими двумя). Первый запуск скачивает модель в кэш Hugging Face. Аудио хранится только в памяти и удаляется после распознавания, наружу ничего не отправляется.
- **Модель и скорость** (измерено на Ryzen 7 9800X3D, фразы 2–3 с):

  | Режим | Задержка на фразу | Замечание |
  |---|---|---|
  | `small`, CPU, int8 (по умолчанию) | ≈1,7 с | точная на русском, прогрева нет |
  | `base`, CPU, int8 | ≈0,55 с | быстрее, но чаще ошибается («Постеф музыку») |
  | `small`, GPU (RTX 5070 Ti, CUDA 12) | ≈0,05–0,4 с | при старте прогрев ≈14 с |

  GPU: `.\scripts\setup.ps1 -Gpu`, затем `--device cuda` или `JARVIS_STT_DEVICE=cuda`. Если CUDA-библиотек нет, JARVIS сам переключается на CPU. `--device auto` выбирает GPU только если он реально рабочий.
- **Ответы голосом** — локальный TTS Windows (SAPI). В системе сейчас установлен голос для русского; для украинского нужного голоса нет, и тогда ответ только текстом. Отключить голос: `--no-tts`.
- **Разговор и свободные фразы (Ollama).** Включено по умолчанию (`JARVIS_OLLAMA_ENABLED=true`, модель `qwen3.5:9b`). Обычные команды разбираются быстрыми правилами. Всё остальное уходит в локальную модель: она либо выбирает зарегистрированное действие («хочу поболтать с друзьями в голосовом чате» → открыть Discord), либо просто отвечает как собеседник, текстом и голосом, с памятью последних 6 реплик (только в оперативной памяти). Ответ-разговор ничего не выполняет, а выбранное моделью действие проверяется так же, как любой другой вход. Адрес Ollama только локальный (`127.0.0.1`/`localhost`). Если Ollama не запущена, базовые команды работают как обычно. Отключить: `--no-ollama` или `JARVIS_OLLAMA_ENABLED=false` в `.env`. Модель подгружается в фоне при старте.

## Модель безопасности

- Все каналы вызывают `ActionService` (`actions/service.py`): реестр известных действий с типизированными параметрами. Приложения, сценарии, игры и допустимые значения берутся из проверенных YAML. Произвольные команды PowerShell/CMD, пути к exe, скрипты и аргументы командной строки из текста, микрофона, Telegram или ответа Ollama не принимаются: лишние параметры отклоняются, неизвестный `app_id` и громкость вне 0–100 тоже.
- Чувствительные действия (выключение, перезагрузка, закрытие приложения, сценарии с `require_confirmation`) никогда не выполняются с первого запроса.
  - Telegram: отдельное подтверждение кнопкой, привязано к пользователю, одноразовое, действует `CONFIRMATION_TTL_SECONDS`.
  - JARVIS: локальное подтверждение только с клавиатуры, введи показанный 4-значный код за `LOCAL_CONFIRMATION_TTL_SECONDS`. Голос и ответ Ollama могут лишь запросить действие. После трёх неверных кодов запросы сбрасываются.
- Выключение и перезагрузка планируются с задержкой `SHUTDOWN_DELAY_SECONDS` (30 с), отмена: «отмени выключение» или `shutdown /a`.
- Авторизация проверяется в каждой команде и каждой кнопке, действует лимит `RATE_LIMIT_COMMANDS_PER_MINUTE`.
- Токен хранится в `.env` вне Git и маскируется в логах. Расшифровки голоса в логи не пишутся, только выполненные действия.

## Проверки

```powershell
.\scripts\check.ps1            # тесты и диагностика
.\scripts\check.ps1 -Voice     # + цепочка WAV → распознавание → действие (нужны модель и русский голос SAPI)
```

Тесты покрывают валидацию параметров, подтверждения (срок, одноразовость, привязка к пользователю, запрет голосового подтверждения), авторизацию Telegram (реальный диспетчер aiogram с подменой сети), разбор русских и украинских фраз, фильтр ответа Ollama, валидацию YAML и маскирование токена.

## Известные ограничения

- Голосовое управление рассчитано на Windows 11.
- Разговор зависит от Ollama и модели: ответы идут с задержкой в несколько секунд, а за фактами модель может ошибаться.
- Пауза и «следующий трек» работают с тем плеером, который Windows считает текущим (браузер, Spotify, медиаплеер). Если ничего не играет, JARVIS так и отвечает.
- Украинский TTS-голос в Windows не установлен по умолчанию; распознавание украинской речи работает, а ответы по-украински выводятся только текстом.
- `alerts.yaml` и фоновый мониторинг пока не подключены.
